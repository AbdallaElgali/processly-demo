## Decisions
- **D6 customer join: deleted** in `app/projects/[projectId]/layout.tsx` and `app/projects/page.tsx` (list cards and search now use the list payload's `customer`, which 3.5 populates). **Kept:** `hooks/Customers.tsx` / `GET /customers/`, used only by `NewProjectDialog` (the customer dropdown and "create customer"). `customer_id` stays on the type (the create body sends it). The layout still falls back to the list entry's `customer` for the moment before details load.
- **F0c precedence:** order is flagged, pending, empty, reviewed. So an empty row that is PENDING is **pending**, and the "Empty" bucket now holds only empty rows someone already decided (ACCEPTED/MODIFIED/REJECTED). In practice Empty will usually be 0 on a fresh project; the legend hints say so. Say if you would rather keep a separate "empty" count.
- **"Save a copy"** is client-side (create template, then one rule upsert each): no backend route exists. If a rule upsert fails midway the new template stays with the rules copied so far and the error text is shown. Offered for the system default only, not for other people's templates.
- Rule upserts for copy send all columns including `is_active`. Rules whose alias clashes cannot occur (same source template).
- 422/404/403 texts: templates use `failure()` ("Failed to ...: <detail>") and flags use `errorMessage` (the bare `detail`); both show the backend text.
- `groupFields` no longer takes the canonical list, so grouping works before `GET /extraction-templates/parameters` returns (the "no canonical yet" ungrouped branch is gone from both tables). `useCanonicalParameters` stays for descriptions, units, "Not in this project" and the rule picker.
